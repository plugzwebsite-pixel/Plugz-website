## Included changes

1. Creator Terms: replaced the placeholder with all 12 clauses and Website Acceptance text from the supplied `Pluggz_Creator_Terms_and_Membership_Agreement.docx`. The entity is CEO Live Ltd. Signup and profile-release consent include the supplied licence acknowledgement. The signup button matches the agreement's Create Account wording.
2. Agreement version: page, creator signup and creator release share one version constant in `src/lib/creator-terms.ts`. The proposed publication version is `2026-09-10`; update it if the actual release occurs later. Historical acceptances are not rewritten. Newly admin-created/imported creators have a null version until they accept. No automatic re-acceptance campaign was implemented.
3. Category New in: sorts by listing creation time descending instead of reversing click popularity.
4. Homepage: renders the saved hero eyebrow and promotional strip text/link.
5. Product deduplication: `findOrCreateProduct` uses the existing www/bare-host twin lookup. The original working destination hostname is retained. This fixes sequential twin lookup; it does not introduce a canonical URL uniqueness constraint for concurrent product creation.
6. Sales import: dotted thousands such as `1.234` become 123400 pence rather than 123 pence. Existing stored sales are not recalculated.
7. Product views: added to creator dashboard, admin products table and product export.
8. View deduplication: nullable unique SHA-256 dedup key includes listing, session and UTC hour, alongside the rolling-hour lookup. Simultaneous same-hour beacons collide at the database constraint. A cross-hour boundary race remains outside this guarantee. Invalid non-string listing IDs are rejected instead of throwing on `.trim()`.
9. Stripe webhook: absent signing configuration returns retryable 503 instead of silently acknowledging/discarding events. Signature verification uses Stripe's local verifier and no longer depends on an outbound API key being configured. Invalid signatures still return 400; processing failures remain retryable.
10. Creator UX copy: removed the stale Wise-only payout promise; chart accessibility label no longer claims a fixed 30-day period when the visible chart uses 14 days.

1. Obtain access to the existing origin host and verify `/srv/pluggz`, current commit, process owner and clean/dirty server state. Preserve server-only changes and uploads. Confirm the actual hosting target before executing a deployment.
2. Take a database backup and note the current deploy revision for rollback. Inspect schema drift before applying changes.
3. Fetch/fast-forward the verified release commit. The repository's `deploy/deploy.sh` performs pull, dependency installation, Prisma schema sync, build, PM2 reload and health check. Review the current server state before invoking it.
4. The new nullable `ProductView.dedupKey` column and unique index MUST be installed before enabling the new writer. Prisma `db push` can warn about new unique constraints. Inspect the SQL and existing duplicates; do not blanket-accept data-loss warnings or remove historical views. Existing rows should retain null keys.
5. Rebuild on the production server with production environment settings; do not upload the locally prerendered development `.next` directory.
6. Preserve server `.env` and `public/` uploads. Never use `rsync --delete` against `public/`.
7. Confirm the actual release date matches `CREATOR_TERMS_VERSION`. Reload PM2 only after a successful build/schema step.
8. Smoke-check homepage, legal page (CEO Live Ltd, full clauses, correct version and no placeholder), signup, login, creator dashboard and admin products. Check application logs and confirm new view inserts are not silently failing on schema drift.
