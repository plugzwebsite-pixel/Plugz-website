started on a private port, tested, and then promoted with an automatic rollback

action. The guide covers the Shopify custom-pixel route and the preferred

## Release observations

- The external-domain run passed 243 of 245 checks. Its two Shopify-pixel
  assertions shared one cause: the test deliberately sends 25 requests from
  invented forwarded IPs, but Cloudflare correctly replaces those untrusted
  headers with the single test host IP and the burst guard then suppresses the
  next synthetic click. The same deployed build passed the complete tracking
  suite 33 of 33 through its trusted proxy path. This is a test-environment
  artefact, not a shopper-flow failure.
- Browser-control initialization in the Codex desktop runtime failed with a
  local kernel-assets path error on two clean attempts. Route rendering,
  authenticated page content and form/API behaviour were still exercised by
  the release suite, but a fresh cross-browser screenshot pass should be done
  when that workstation runtime is available.
- The production Stripe configuration is live. The two suites that create
  Stripe accounts, settle invoices or move funds correctly refused to run.
  Final Instagram → click → order → commission → payout validation must use a
  coordinated creator/product/order and either Stripe test mode or an approved
  low-value live transaction.

## Open items

1. **Legal copy required:** Consumer Terms are live, but there are no Privacy
   Policy or Cookie Policy routes. Their approved legal wording must be supplied
   before implementation; it should not be invented by engineering.
2. **Entity confirmation:** Creator Terms name CEO Live Ltd, while public/email
   footers still display Pluggz Ltd. Confirm whether the footer is a trading-name
   label or must be changed to the legal entity.
3. **Cloudflare Stream readiness:** Upload failure is handled without a server
   crash and existing videos remain safe, but an actual upload-to-READY test
   requires active Stream capacity and credentials.
4. **Build warning:** Next.js reports that the guarded `node:dns` dynamic import
   in `src/instrumentation.ts` is unsupported in Edge Runtime. The Node-only
   guard prevents execution there, but the warning should be removed in a later
   maintenance pass.
5. **Tooling advisories:** The runtime Next.js and image-processing security
   advisories were patched. Remaining audit findings are transitive build-time
   dependencies through PostCSS/Prisma; the automatic proposal downgrades
   Prisma and was therefore not applied without a controlled migration test.
